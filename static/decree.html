The Paxos Decree Lifecycle

A decree in Paxos goes through several phases before being learned by all priests:

Phase 1 (Prepare): The proposer sends a prepare request with a ballot number to all priests. Priests respond with promises not to accept any lower-numbered ballots, and report any previously voted-for decrees.
Phase 2 (Accept): The proposer sends an accept request with the decree value and ballot number. Priests vote for the decree if they haven't promised to a higher ballot number.
Phase 3 (Learn): Once a quorum of priests has voted, the decree is chosen. The proposer sends learn messages, and priests record the decree in their ledger (persistent storage).

Key Properties

Consistency (Safety): If a decree is learned, all priests who learn a decree for the same slot will learn the same value. This is guaranteed by condition B3 from the paper: if any priest in a ballot's quorum voted in an earlier ballot, the new ballot must propose the same decree.

Progress (Liveness): As long as a quorum of priests remains alive and can communicate, a decree will eventually be learned. New ballots with higher numbers are attempted until one succeeds.

Durability: Once a decree is learned and written to persistent storage, it remains even if priests fail and restart. This allows the system to be fault-tolerant.

The Critical Invariant (B3): "For every ballot B, if any priest in B's quorum voted in an earlier ballot in B, then the decree of B equals the decree of the latest of those earlier ballots."

This ensures that once a decree has been accepted by a quorum in any ballot, all future ballots will propose that same decree. This is what provides consistency.
