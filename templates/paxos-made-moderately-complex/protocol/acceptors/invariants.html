Acceptor Invariants

Ballot Ordering

$\mathbf{A1}$: an acceptor can only adopt strictly increasing ballot numbers;

This invariant ensures that acceptors never move backward in ballot numbers. Once a higher ballot is observed, all lower ballots are permanently rejected.

Ballot Consistency

$\mathbf{A2}$: an acceptor α can only add (b, s, c) to α.accepted (i.p., accept (b, s, c)) if b = α.ballot num;

This invariant ensures that an acceptor only accepts pvalues that match its current ballot number. An acceptor checks if a pvalue is stale by it's current α.ballot_num. The protocol enforces this by requiring an acceptor to adopt a higher ballot before accepting proposals for it.

Append Only

$\mathbf{A3}$: acceptor α cannot remove pvalues from α.accepted (we will modify this impractical restriction later);

This invariant ensures that acceptor state is monotonic. Much like A1, this helps us simplify the acceptor logic and will be amended with an optimization later via garbage collection.

Command Identity

$\mathbf{A4}$: Suppose α and α' are acceptors, with (b, s, c) ∈ α.accepted and (b, s, c') ∈ α'.accepted. Then c = c' .

Informally, given a particular ballot number and slot number, there can be at most one proposed command under consideration by the set of acceptors.

Value Preservation

$\mathbf{A5}$: Suppose that for each α among a majority of acceptors, (b, s, c) ∈ α.accepted. If b' > b and (b', s, c') ∈ α' .accepted, then c = c'

We will consider this crucial invariant in more detail later.

This invariant is a corollary to Theorem Two in Lamport's Part Time Parliament paper. Here it's defining that leaders are constrained by the history of past acceptance. Remember Invariants are just axioms, the code is what will make this actually true. Right now they're more magic invocations.

Without this invariant, a leader could overwrite a command that was already accepted by a majority, causing different replicas to execute different commands for the same log slot.

A5 is Bidirectional
It is important to realize that an invariant like A5 works “both ways.” In one direction, if a majority of acceptors have accepted a particular pvalue (b, s, c), then any pvalue for a later ballot will contain the same command c. In the other direction, suppose some acceptor accepts (b' s, c') before there is a majority of acceptors that have accepted some other pvalue on an earlier ballot. That does not rule out that at some later time there will be a pvalue (b, s, c) on a ballot b, b < b' , that is accepted by a majority of acceptors. The invariant requires that c = c' in that case as well.
RENESSE, P. 5 §2

A5 is about Value Preservation across ballots, a quorum being reached for a value means any ballots with a lower number that reaches quorum cannot choose a different command for it's slot. The invariant is bidirectional and constrains all quorums, forcing c' = c = c''
