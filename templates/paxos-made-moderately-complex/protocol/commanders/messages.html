Commander Messages

Commanders interpret the response from acceptors. There are three states such messages can be in accepted or rejected which depends on the value of the ballot_number sent back. It will be ignored if it is less than the Commander's ballot number. Though for most implementations the commander thread would not have been spawned to begin with. Accepted if it is equal to the commanders ballot. And finally rejected if the ballot is greater then the commanders

Accepted

Phase 2 B with Current Ballot
If a commander receives (p2b, α, b) from all acceptors in a majority of acceptors, then the commander learns that command c has been chosen for slot s. In this case the commander notifies the replicas and exits. In order to satisfy Invariant R1, we need to enforce that if a commander learns that c is chosen for slot s, and another commander learns that c'is chosen for the same slot s, then c = c'.
This is a consequence of Invariant A5: if a majority of acceptors accept (b, s, c), then for any later ballot b' and the same slot number s, acceptors can only accept (b', s, c). Thus if the commander of (b' , s, c') learns that c'has been chosen for s, it is guaranteed that c = c'and no inconsistency occurs, assuming—of course—that Invariant C2 holds
RENESSE, P. 6 §2 - Leaders and Commanders

Once enough accepted messages are received by the commander to reach quorum it will notify the replicas with a (decision, s,c) message and stop it's process.

Since R1 states that There are no two different commands decided for the same slot this invariant must hold. This is done through the acceptors A5 invariant. An acceptor is nothing more then a filter method at it's heart and it's main purpose is to keep A5 in place. Renesse points out that C2 must also hold but that's is the purview of the Leader who spawns the commander and not the commander logic itself.

Rejected

Phase 2 B with Current Ballot
If a commander receives (p2b, α', b') from some acceptor α', with b' $\neq$ b, then it learns that a ballot b' (which must be larger than b as guaranteed by acceptors) is active. This means that ballot b may no longer be able to make progress, as there may no longer exist a majority of acceptors that can accept (b, s, c). In this case, the commander notifies its leader about the existence of b', and exits.
RENESSE, P. 6 §2 - Leaders and Commanders

If a commander receives a rejected response there are two actions it can take.

If it was a delayed message and has a smaller ballot then the current commander ballot it would be ignored.

If it is greater then progress might no longer be possible. While additional messages for the current ballot might still be in flight or being answered by acceptors that cannot be assumed. The commander will inform the leader of this with sent ballot number so it might set that to the current ballot and end the process.

Progress
Under the assumption that at most a minority of acceptors can crash, messages are delivered reliably, and the commander does not crash, the commander will eventually do one or the other.
RENESSE, P. 6 §2 - Leaders and Commanders
