$Propose(c)$

Execution Loop
A replica runs in an infinite loop, receiving messages. Replicas receive two kinds of messages: requests from clients, and decisions.
When it receives [(request, c)] a request for command c from a client, the replica invokes propose(c). This function checks if there has been a decision for c already. If so, the replica has already sent a response and the request can be ignored.
If not, the replica determines the lowest unused slot number s', and adds proposal (s', c), to its set of proposals. It then sends a (propose, s' ,c) message to all leaders. Leaders are described below.
RENESSE, P. 3 §2

A replica is always waiting for messages. As soon as a message from a client arrives, it starts the process of creating a propose message to send to other replicas.

The first part of this process is to check if this work has already been done by a previous message. Recall that $c = (\kappa, \text{cid}, \text{op})$. The replica checks if any slot already contains this command with the attached $\kappa$ and $\text{cid}$. If so, it does nothing; otherwise, it proceeds to construct the propose message.

The propose message will be of the form $(s', c)$, where $s'$ is this replica's lowest available slot and $c$ is the client command $(\kappa, \text{cid}, \text{op})$. This message is then sent to all the leaders of the cluster.
