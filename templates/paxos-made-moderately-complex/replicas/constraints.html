Replica Constraints

Slot Uniqueness

$\mathbf{R1}$: $\forall s,\;\rho_1,\;\rho_2,\;c_1,\;c_2:\; \big( (s, c_1)\in \rho_1.\text{decisions} \;\wedge\; (s, c_2) \in \rho_2.\text{decisions} \big) \;\Rightarrow\; c_1 = c_2$

There are no two different commands decided for the same slot

For any slot s and any two replicas ρ₁ and ρ₂, if replica ρ₁ has learned that command c₁ was decided for slot s, and replica ρ₂ has learned that command c₂ was decided for the same slot, then c₁ and c₂ must be the same command.

Slot Completeness

$\mathbf{R2}$: $\forall \rho,\, s:\; 1 \le s < \rho.\text{slot\_num} \;\Rightarrow\; \exists c:\; (s, c) \in \rho.\text{decisions}$

All commands up to slot num are in the set of decisions

For any replica p and any slot s where s is at least 1 and less then the current slot number slot_num there exists a command such that the pair (s, c) is in ρ.decisions

State Ordering

$\mathbf{R3}$: For all replicas $\rho$, $ρ$.state is the result of applying the commands in ($s$, $c_s$), ∈ $\rho$.decisions for all $s$ up to $\text{slot\_num}$ to $\text{initial\_state}$, in order of slot number

Each replica's state is obtained by applying all decided commands in order of their slot numbers to the initial state.

Slot Identity

$\mathbf{R4}$: For each $ρ$, the variable $\rho$.slot num cannot decrease over time.

Slot Identification / Time cannot go backwards. IE they are monotonically increasing.

Invariants
From Invariants R1-3, it is clear that all replicas apply operations to the application state in the same order, and thus replicas with the same slot number have the same state. Invariant R4 captures that a replica cannot go back in time.
