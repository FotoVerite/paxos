Decisions

Decision Process
Decisions may arrive out-of-order and multiple times. For each decision message, the replica adds the decision to the set of decisions. Then, in a loop, it considers which decisions are ready for execution before trying to receive more messages. If there is a decision c'' corresponding to the current slot num, the replica first checks to see if it has proposed a different command c''. If so, it re-proposes c'', which will be assigned a new slot number. Next, it invokes perform(c' )
RENESSE, P. 3 §2

Decision messages may arrive out of order and may be duplicated. When a decision message arrives, the replica records the decided pair (s, c) in its set of decisions.

After recording a decision, the replica checks whether it can make progress executing commands. It does this by repeatedly testing whether there is a decision for the current slot_num.

If a decision exists for the current slot, the replica first checks whether it previously proposed a different command for that same slot. If so, that command has lost the decision race and must not be discarded. Instead, the replica re-proposes it for a new, higher-numbered available slot. This slot is not necessarily the next consecutive slot, since other commands may have been proposed in the meantime.

Finally, the replica invokes perform(c) on the decided command and continues checking for the next executable decision.
