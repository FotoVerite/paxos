Non Volatile Memory

All replicas need to store for variables in non volatile memory so they can recover from failure.

ρ.state

the replica’s copy of the application state, which we will treat as opaque. All replicas start with the same initial application state
RENESSE, P. 3 — §3

The state is the application of all commands it has learned. For the purposes of the paper it doesn't matter what type of application we are talking about, simply that ce replicas process all decisions in order, they end up with the same state.

ρ.slot_number

The replica’s current slot number (equivalent to the version number of the state, and initially 1). It contains the index of the next slot for which it needs to learn a decision before it can update its copy of the application state
RENESSE, P. 3 — §3

The slot number indicates the position of the next decision the replica must learn before applying further commands. Depending on implementation, tracking this can be more complex than just recording the latest slot.

ρ.proposals

A set of proposals that the replica has made in the past (initially empty);
RENESSE, P. 3 — §3

These are the (slot, command) pairs this replica has previously attempted to propose.

ρ.decisions

A set of proposals that are known to have been decided (also initially empty)
RENESSE, P. 3 — §3

These are the (slot, command) pairs this replica have chosen by quorum agreement.
