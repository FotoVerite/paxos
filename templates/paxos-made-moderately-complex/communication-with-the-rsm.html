Communication

RPC
A client process, using a library “stub routine,” can send a command to such a server over a network and await an output.
RENESSE, P. 1 §1

Stub Routine here is referring to a RPC, a Remote Procedure Call. Think of it as a function that acts like it's local but calls a remote server to actually apply the inputs. Such as in our KVStore the GETS and the PUTS

Client Message
A command is a triple (κ, cid, operation), where κ is the identifier of the client that issued the command and cid a client-local unique command identifier (such as a sequence number). That is, there cannot be two commands that have the same client identifier and command identifier but have different operations.
However, a client can issue the same operation more than once by using a different command identifiers. The command identifier must be included in the response from the server to a command so the client can match responses with commands
RENESSE, P. 1 §1

RPCs should have the format of an client identifier which should be unique per client, a command identifier which should increment per command and the operation itself. Since this is an asynchronous environment the return of the RPC must include the cid so that the client can match each response to the command it issue.

If a client retries an operation using the same command identifier, the state machine must treat it as the same command and avoid applying it twice. Issuing the same operation with a new command identifier, however, represents a new command and will be processed again by the replicated state machine.
