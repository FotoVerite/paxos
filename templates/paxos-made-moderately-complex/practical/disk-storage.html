Disk Storage & Recovery

In the core protocol, we assume nodes don't crash. But real systems crash. Hard drives fail. Power goes out. Paxos needs to handle this.

The solution is to write critical state to disk. If a node crashes and recovers, it can read its disk and resume without violating safety.

What must be persisted?

Not all state needs to be on disk. The key rule: anything that affects safety must be persisted before you act on it.

For acceptors, this means:

  • The highest ballot you've adopted.
  • All pvalues (ballot, slot, value) you've accepted.

For replicas, this means:

  • The decisions you've received (which commands are in which slots).
  • Your current state (the result of executing all decided commands).

For leaders, nothing needs to be persisted. If a leader crashes, another leader takes over. There's no safety risk.

Crash recovery

When a node starts up, it reads its disk:

  • Acceptors learn which ballot they previously adopted. They refuse to adopt lower ballots.
  • Replicas learn which commands they've already executed. They don't re-execute them.

This maintains all the invariants. An acceptor that crashes and recovers is treated exactly like a slow acceptor—it just participated in old ballots, not new ones.

Write-ahead logging

The rule is strict: before you act on a message, write the relevant state to disk and wait for acknowledgment. Only then process the message.

For example, an acceptor receives "adopt ballot (5, λ)". Before it responds "OK, I adopted it", it writes "(5, λ)" to disk. If the acceptor crashes right after responding but before the disk write completes, that's a problem—upon recovery, it would forget it adopted the ballot and might violate safety.

So: write to disk, then respond. Always.

Performance cost

Disk writes are slow. This is a major bottleneck in real Paxos implementations. Every ballot adoption, every value acceptance—they all require disk I/O.

In practice, people batch writes, use SSDs, or keep a write-ahead log in memory (which is itself replicated across machines). But the core principle remains: safety is the priority.
