Leader Election

The solution to the liveness problem is to designate one leader. But "elect" is the wrong word. In an asynchronous system, you can't guarantee that exactly one leader is elected at any moment.

Instead, Paxos uses weak leader election. The guarantee is weaker: eventually, one leader will be active long enough for progress to be made.

How it works

Each node has the ability to claim leadership. It picks a ballot number and says "I'm the leader for this ballot." It doesn't ask for permission. It just declares it.

A node can claim leadership if it's not currently following another leader. So at any moment, multiple nodes might claim they're the leader. But they claim different ballots.

The key rule: the node with the highest ballot number is the active leader. Other nodes, seeing higher ballots, become passive and route proposals to the active leader.

Passive followers

When a node receives a message from a leader with a higher ballot, it adopts that ballot and becomes a follower. It stops running its own scouts. Instead, it forwards proposals from clients to the current leader.

This is where weak leader election comes in: as long as the active leader keeps sending scouts successfully (getting majorities to adopt its ballot), other nodes stay passive. The system behaves like it has a single leader.

If the leader crashes or gets isolated, its ballots stop being adopted (a higher ballot from another node will eventually be seen), and a new node takes over.

Why this is "weak"

During transitions (when one leader is failing and another is taking over), there might be no active leader. Or there might be competing leaders sending scouts. But eventually—and this is guaranteed by timeouts (next page)—one leader will establish itself long enough for proposals to make progress.

This is weak leader election: not a guarantee of exactly one leader at all times, but a guarantee that eventually the system will behave as if it has one.
