The Problem

There are several ways to coordinate clients with a replicated state machine. A naïve approach is client multicast.

SMR replication
In SMR replication, the stub routine is replaced with another to provide the illusion of a single remote server that is highly available. The stub routine sends the command to all replicas (at least one of which is assumed to not crash) and returns only the first response to the command.
RENESSE, P. 2 §1

Here a client will send to all known replicas and whichever response comes back first will be the one exposed is returned to the client. It is assumed that at least one replica processes the command correctly, even if others are slow or crash.

Multi-Clients
The difficulty comes with multiple clients, as concurrent commands may arrive in different orders at different replicas, and thus the replicas may end up taking different transitions, producing different outputs as a result and possibly ending up in different current states. A protocol like Paxos ensures that this cannot happen: all replicas receive commands in the same order and thus the replicated state machine behaves logically identical to a single remote state machine that never crashes
RENESSE, P. 2 §1

In an asynchronous environment as soon as one adds in multiple clients one can not guarantee that messages sent in a certain order will be processed in the same order. This can cause replicas to diverge and reach different states. The Paxos algorithm is one solution to ensure that all replicas agree on the ordering and hence remain consistent.
