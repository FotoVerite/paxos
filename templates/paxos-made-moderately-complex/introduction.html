Introduction

If you finished Paxos Made Simple, you now know the core algorithm. Lamport's paper is brilliant at stripping away implementation details and showing you the invariants. But there's a gap between understanding Paxos and implementing it.

That's where this paper comes in. Robbert van Renesse's "Paxos Made Moderately Complex" fills that gap. It gives you the full operational description of Multi-Paxos—the version that actually runs in production systems like Chubby and ZooKeeper.

The "moderately complex" part is honest. It's not simple anymore, but it's not impenetrably complex either. Van Renesse walks through the pseudocode, discusses the state machines, and explains the engineering decisions that make Paxos practical.

What you'll learn

  • Replicas and Slots: How commands are ordered across the system using a sequence of slots.
  • The Synod Protocol: Ballots, acceptors, scouts, and commanders. The machinery that actually reaches consensus.
  • Liveness: Why the basic protocol can livelock, and how weak leader election fixes it.
  • Practical Details: Disk storage, crash recovery, reconfiguration, optimizations that make this work in the real world.

Prerequisites

You should understand Paxos Made Simple first. If you haven't read it (or this site), go back and work through it. This builds directly on that foundation.

You also need to be comfortable with pseudocode and state machines. Van Renesse uses both extensively.
