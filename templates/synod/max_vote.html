Section 2. A function partial functional name

$\text{MaxVote}(b, p, \mathcal{B})$

Give the previous constraints this function is defining the following, for a given Ballot id, (Yes the b here is the Same as $B$bal, we're just getting started with his confusing notation) a given priest/node and the set of ballots we will return vote with the largest ballot id of the set.

MaxVote(b, p, B):

formally defined as: $\{ v \in \text{Votes}(\mathcal{B}) : v_{\text{pst}} = p \wedge v_{\text{bal}} < b \} \cup \{ \text{null}_p \}$

This reads as the set of votes in the ballot B cast by priest p with ballot numbers less than b, together with the null vote.

This is not an implementation detail Lamport is specifying what the function must do, not how to implement it.

This also explains why he switches from $B_{\text{bal}}$ to $v_{\text{bal}}$: he’s interested in the vote and the ballot attached to it, while disambiguating the value obtained versus the ballot itself. The vote is just a technicality to get the ballot.
