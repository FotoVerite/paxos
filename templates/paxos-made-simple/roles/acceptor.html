Acceptor

Acceptor Construction

An acceptor's job is to keep track of the last value it voted for and its latest proposal number it has promised to accept.

{% raw %} 

pub struct Acceptor {
    id: i32,
    next_proposal: Option,
    previous_vote: Option<(Proposal, Value)>
}
{% endraw %}

Acceptors are a simple filter; they have no other job besides being non-volatile memory.

It can send two messages and receive two messages:

Prepare

{% raw %} 

Prepare { from: NodeId, proposal: Proposal }
{% endraw %}

When Prepare is received, it will respond with an accept message. If the sent proposal is larger than next_proposal, it will set next_proposal to that proposal.

Promise

{% raw %} 

Promise { from: NodeId, proposal: Proposal, last_voted: Option<(Proposal, Value)> }
{% endraw %}

Promise also enforces the nontriviality and consistency of the proposal. The acceptor sends back information on what it last voted for, if any. From this, the proposer can determine if its current proposal is greater than any seen before.

Accept

{% raw %} 

Accept {
    from: NodeId,
    proposal: Proposal,
    value: PaxosCommand,
}
{% endraw %}

Accept is sent to acceptors to ask if their promise is still valid. If so, they reply with Accepted to one or more learners depending on the implementation.

Accepted

{% raw %} 

Accepted {
    from: NodeId,
    proposal: Proposal,
    value: PaxosCommand,
}
{% endraw %}

Accepted is sent to all learners or a distinguished learner, where it tallies Accepted messages to make sure quorum is reached.
