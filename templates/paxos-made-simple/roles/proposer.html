Proposer

A proposer's main job is to increment the proposal number and collate proposal values from all other reachable nodes. From the collated values, it will choose the latest voted-on value, or its own if none have been proposed.

Proposal's Number

A Proposal is simple a combination of the current iteration and the role's/node's identification number

{% raw %} 

struct Proposal {
    pub number: i32,
    pub node_id: i32,
}
{% endraw %}
{% raw %}

Proposer Construction


pub struct Proposer {
    id: i32,
    last_tried: i32,
}
{% endraw %}

A proposer needs to keep track of two things: its ID and its last_tried proposal number. From there, it can always generate its next proposal.

It can send two messages and receive one message:

Prepare

{% raw %} 

Prepare { from: NodeId, proposal: Proposal }
{% endraw %}

Prepare is all about enforcing the nontriviality and consistency of the proposal. It asks acceptors if this proposal is the largest they have seen, and if so, to send back their last vote if it exists.

All messages include a from identifier to disambiguate messages from different nodes that might contain identical information besides this identifier.

Promise

{% raw %} 

Promise { from: NodeId, proposal: Proposal, last_voted: Option<(Proposal, Value)> }
{% endraw %}

Promise also enforces the nontriviality and consistency of the proposal. It sends back information on what it last voted, if any. From this, the proposer can determine if its current proposal is greater than any seen before. If so, it can send the Accept message; if not, it can increment its proposal and try again. A simple optimization is to 1+ the greatest last_voted number observed.

All messages after Promise include the proposal to validate that the message is non-stale. In the proposer, this is compared to last_tried.

Accept

{% raw %} 

Accept {
    from: NodeId,
    proposal: Proposal,
    value: PaxosCommand,
}
{% endraw %}

Accept is sent to acceptors to ask if their promise is still valid. If so, they reply with Accepted to one or more learners depending on the implementation. (We will cover learners in detail later.)
