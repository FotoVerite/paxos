Proposer

A proposer's main job is to increment the ballot number and collate proposal values from all other reachable nodes. From the collated values, it will choose the latest voted-on value, or its own if none have been proposed.

{% raw %} 

struct Ballot {
    pub number: i32,
    pub node_id: i32,
}
    

pub struct Proposer {
    id: i32,
    last_tried: i32,
}
{% endraw %}

A proposer needs to keep track of two things: its ID and its last_tried ballot number. From there, it can always generate its next ballot.

It can send two messages and receive one message:

Prepare

{% raw %} 

Prepare { from: NodeId, ballot: Ballot }
{% endraw %}

Prepare is all about enforcing the nontriviality and consistency of the ballot. It asks acceptors if this ballot is the largest they have seen, and if so, to send back their last vote if it exists.

All messages include a from identifier to disambiguate messages from different nodes that might contain identical information besides this identifier.

Promise

{% raw %} 

Promise { from: NodeId, ballot: Ballot, last_voted: Option<(Ballot, Value)> }
{% endraw %}

Promise also enforces the nontriviality and consistency of the ballot. It sends back information on what it last voted, if any. From this, the proposer can determine if its current ballot is greater than any seen before. If so, it can send the Accept message; if not, it can increment its ballot and try again. A simple optimization is to 1+ the greatest last_voted number observed.

All messages after Promise include the ballot to validate that the message is non-stale. In the proposer, this is compared to last_tried.

Accept

{% raw %} 

Accept {
    from: NodeId,
    ballot: Ballot,
    value: PaxosCommand,
}
{% endraw %}

Accept is sent to acceptors to ask if their promise is still valid. If so, they reply with Accepted to one or more learners depending on the implementation. (We will cover learners in detail later.)
