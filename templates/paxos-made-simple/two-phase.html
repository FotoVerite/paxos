Two Phase Algorithm

Lamport now codifies these different algorithms into two steps.

Algorithm
Putting the actions of the proposer and acceptor together, we see that the algorithm operates in the following two phases.
Phase 1. (a) A proposer selects a proposal number n and sends a prepare request with number n to a majority of acceptors. (b) If an acceptor receives a prepare request with number n greater than that of any prepare request to which it has already responded, then it responds to the request with a promise not to accept any more proposals numbered less than n and with the highest-numbered proposal (if any) that it has accepted.
Phase 2. (a) If the proposer receives a response to its prepare requests (numbered n) from a majority of acceptors, then it sends an accept request to each of those acceptors for a proposal numbered n with a value v, where v is the value of the highest-numbered proposal among the responses, or is any value if the responses reported no proposals. (b) If an acceptor receives an accept request for a proposal numbered n, it accepts the proposal unless it has already responded to a prepare request having a number greater than n.
LAMPORT, P. 3 — §2.2

Phase One is very understandable from the previous description of the proposal algorithm. A proposal is made by a proposer if it's greater than previous seen acceptors they will send back their promise with the last previous value they accepted if applicable.

Phase Two A is also understandable. If a quorum is reach from these promise messages by the proposer, the proposer will send an accept message with the proposal number and the value from the greatest previous proposal or it's own if no previous proposal exists.

Phase Two B is where the pedagogy breaks down. An acceptor “accepts” a proposal—but what does accepting actually mean here? In this phase, acceptance is only an internal state change. The acceptor records the proposal number and value in order to preserve safety invariants. This action has no externally visible effect. Accepting does not mean the value is chosen, learned, or made durable for the system. Where does the learner fit in which he has ignored so far for the entire paper. TAs written, the algorithm is complete only in the narrow sense of safety, which leaves it feeling unsatisfying and also not useful in a real world context. While he will tackle the learner in the next section it is also in the most roundabout manner.
