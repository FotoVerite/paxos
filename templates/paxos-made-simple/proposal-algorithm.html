Proposal Algorithm

Issuing Proposals
To maintain the invariance of P2c , a proposer that wants to issue a proposal numbered n must learn the highest-numbered proposal with number less than n, if any, that has been or will be accepted by each acceptor in some majority of acceptors. Learning about proposals already accepted is easy enough; predicting future acceptances is hard. Instead of trying to predict the future, the proposer controls it by extracting a promise that there won’t be any such acceptances. In other words, the proposer requests that the acceptors not accept any more proposals numbered less than n.
LAMPORT, P. 3 — §2.2

This is technically an optimization step. It causes the acceptor to ignore any proposals with numbers lower than the latest one, even if they are in flight or were previously accepted.

Prepare
1. A proposer chooses a new proposal number n and sends a request to each member of some set of acceptors, asking it to respond with:
(a) A promise never again to accept a proposal numbered less than n, and
(b) The proposal with the highest number less than n that it has accepted, if any.
I will call such a request a prepare request with number n.
LAMPORT, P. 3 — §2.2

A Prepare request queries all acceptors to report back its' highest known proposal with value if any and to respond to any requests with a lower number then this proposal as stale. The acceptor will use that proposal number to check the freshness of the next response.

Validation
If the proposer receives the requested responses from a majority of the acceptors, then it can issue a proposal with number n and value v, where v is the value of the highest-numbered proposal among the responses, or is any value selected by the proposer if the responders reported no proposals.
LAMPORT, P. 5 — §2.2

A proposer collates responses, if it has met a quorum of response it can determine if a value has already been proposed and has consistency by selecting the largest previous proposals value in the response or use it's own if there are no previous proposals.

Accept
A proposer issues a proposal by sending, to some set of acceptors, a request that the proposal be accepted. (This need not be the same set of acceptors that responded to the initial requests.) Let’s call this an accept request.
LAMPORT, P. 5 — §2.2

Accept is a message that contains the same proposal number with a proposed value that should match the constraints of consensus and nontriviality. Consensus, because a quorum has been used and Nontriviality because the value was either proposed before or through this proposer.
