What does P stand for

Requirement? Parameter? Constraint
In the absence of failure or message loss, we want a value to be chosen even if only one value is proposed by a single proposer. This suggests the requirement: P1. An acceptor must accept the first proposal that it receives.
P1 and the requirement that a value is chosen only when it is accepted by a majority of acceptors imply that an acceptor must be allowed to accept more than one proposal.
LAMPORT, P. 2 — §2.2

Lamport decides to create this new, variable? tag? invariant?, known as P that he calls a requirement. It's not. You can even see him split it from the value requirements in the next paragraph. What he actually are using these for are properties of a role that must be true for the constraints of nontriviality, consensus and validity to remain true. P1 refers to the acceptor, P2 to the proposer. P3 the learner is ignored. Which is it's own problem.
