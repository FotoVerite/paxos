Filling Gaps

No-op Commands
The leader could take the next two commands requested by clients to be commands 136 and 137. Instead, we let it fill the gap immediately by proposing, as commands 136 and 137, a special "noop" command that leaves the state unchanged. (It does this by executing phase 2 of instances 136 and 137 of the consensus algorithm.) Once these no-op commands have been chosen, commands 138–140 can be executed.
LAMPORT, P. 9 — §3

When gaps appear in the command sequence (due to failures or lost messages), the leader fills them with no-op commands that leave the state unchanged. This allows all replicas to execute commands in order without waiting for missing commands to be proposed.

Resuming Normal Operation
Commands 1–140 have now been chosen. The leader has also completed phase 1 for all instances greater than 140 of the consensus algorithm, and it is free to propose any value in phase 2 of those instances. It assigns command number 141 to the next command requested by a client, proposing it as the value in phase 2 of instance 141 of the consensus algorithm. It proposes the next client command it receives as command 142, and so on.
LAMPORT, P. 10 — §3

With all gaps filled, the leader resumes normal operation, assigning sequence numbers to the next client commands.
