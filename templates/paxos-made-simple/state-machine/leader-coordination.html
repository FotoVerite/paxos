Leader Coordination

The Single Leader Pattern
In normal operation, a single server is elected to be the leader, which acts as the distinguished proposer (the only one that tries to issue proposals) in all instances of the consensus algorithm. Clients send commands to the leader, who decides where in the sequence each command should appear.
LAMPORT, P. 8 — §3

The leader acts as the distinguished proposer, assigning sequence numbers to client commands. This avoids the livelock problem where multiple proposers continuously block each other.

Command Ordering
If the leader decides that a certain client command should be the 135th command, it tries to have that command chosen as the value of the 135th instance of the consensus algorithm. It will usually succeed. It might fail because of failures, or because another server also believes itself to be the leader and has a different idea of what the 135th command should be. But the consensus algorithm ensures that at most one command can be chosen as the 135th one.
LAMPORT, P. 8 — §3

Safety is guaranteed: even if multiple servers think they are the leader, Paxos ensures at most one value is chosen for each position. Liveness requires a single stable leader.
