Proposal Window

Pipeline Depth (α)
The leader can propose command 142 before it learns that its proposed command 141 has been chosen. It's possible for all the messages it sent in proposing command 141 to be lost, and for command 142 to be chosen before any other server has learned what the leader proposed as command 141. When the leader fails to receive the expected response to its phase 2 messages in instance 141, it will retransmit those messages. If all goes well, its proposed command will be chosen. However, it could fail first, leaving a gap in the sequence of chosen commands. In general, suppose a leader can get α commands ahead—that is, it can propose commands i + 1 through i + α after commands 1 through i are chosen. A gap of up to α−1 commands could then arise.
LAMPORT, P. 10 — §3

Alpha (α) represents the proposal window—how many commands ahead the leader can pipeline without waiting for confirmation. Larger α increases throughput but creates larger potential gaps if the leader fails, which must be filled with no-ops.

Bounded Execution
The leader, as well as any other server that learns all the commands the leader knows, can now execute commands 1–135. However, it can't execute commands 138–140, which it also knows, because commands 136 and 137 have yet to be chosen.
LAMPORT, P. 9 — §3

Even though a server may know about commands far ahead, it cannot execute them until all earlier commands in the sequence have reached consensus. This preserves the deterministic ordering required for replicated state machines.
