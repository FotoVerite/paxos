Requirements

Agents

Lamport main idea in this paper is to split the operational concerns of the algorithm into three separate roles.

Agents/Process
Agents operate at arbitrary speed, may fail by stopping, and may restart. Since all agents may fail after a value is chosen and then restart, a solution is impossible unless some information can be remembered by an agent that has failed and restarted
LAMPORT, P. 2 — §2.1

Agents can fail and must have non-volatile memory to allow restarts to deal with crashes and other errors. Without which liveliness cannot be ensured.

Roles

Agent Roles
We let the three roles in the consensus algorithm be performed by three classes of agents:
  • Proposer
  • Acceptor
  • Learner
In an implementation, a single process may act as more than one agent, but the mapping from agents to processes does not concern us here.
LAMPORT, P. 2 — §2.1

Agents can have multiple roles but each role has a separate concern

Proposers proposes values to acceptors and acts as a filter for the correct value if there have been previous votes. If quorum is possible it then will call for a round of votes. This role enforces Nontriviality by the proposal mechanism and Consistency by collecting previous votes from the acceptors.

Acceptors receive proposals from proposers and check whether the ballot is consistent with respect to their promises. This role enforces Consistency by preventing conflicting acceptances.

Learners tally votes and learn a value if quorum is reached and if so learn the value. This roles enforces Consistency and Validity

Non-Byzantine

Non-Byzantine Messages
Messages can take arbitrarily long to be delivered, can be duplicated, and can be lost, but they are not corrupted.
LAMPORT, P. 2 — §2.1

Agents will not lie or act maliciously.

Liveliness

Liveliness while a major concern of a production system is a secondary for the paper and comes up mostly when it pertains to safety. It is treated as an underlying goal: if a value is chosen, it should eventually be learnable.

Liveness
We won’t try to specify precise liveness requirements. However, the goal is to ensure that some proposed value is eventually chosen and, if a value has been chosen, then a process can eventually learn the value.
LAMPORT, P. 2 — §2.1
