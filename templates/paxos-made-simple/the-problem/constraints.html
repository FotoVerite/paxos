Constraints

The Problem
Assume a collection of processes that can propose values. A consensus algorithm ensures that a single one among the proposed values is chosen. If no value is proposed, then no value should be chosen. If a value has been chosen, then processes should be able to learn the chosen value. The safety requirements for consensus are:
  • Only a value that has been proposed may be chosen,
  • Only a single value is chosen, and,
  • A process never learns that a value has been chosen unless it actually has been
LAMPORT, P. 1 — §2.1

This is a reframing in plain language of the three constraints from the Part-Time Parliament constraints in terms of values rather than ballots.
Original constraints explanation . They are the guiding principles of the algorithm and the main goals it sets out to accomplish.

Nontriviality

Only a value that has been proposed may be chosen

Paxos must not invent values. Any chosen value must have been explicitly proposed by some process.

This maps to the B1, Ballot Uniqueness. Both ensure that values originate from valid proposals and are not introduced or altered outside the protocol.

Consistency

Only a single value is chosen

Once a value is chosen for a given instance, no other value may be chosen for that instance.

This maps to the B2, Quorum.

Validity

A process never learns that a value has been chosen unless it actually has been

Validity does not introduce a new safety property about which values may be chosen. Instead, it constrains how and when processes may learn that a value has been chosen.

Given nontriviality (B1) and consistency (B2), validity follows as long as learning occurs only through protocol-defined agreement. It exists to rule out false positives caused by faulty learners, messengers, or premature conclusions.
