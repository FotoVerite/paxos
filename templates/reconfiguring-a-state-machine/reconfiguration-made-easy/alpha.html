Alpaha

Definition

To allow concurrent processing of commands, we define the state machine (by introducing additional state) so that executing $rcfg(C)$ as command number $i$ causes cfg to change after executing command $i$ + $\alpha$ − 1, for some positive $\alpha$. A reconfiguration command thus takes effect $\alpha$ commands later, allowing the concurrent processing of up to $\alpha$ commands ... We call this method $\mathcal{R_\alpha}$. As the notation implies, $\mathcal{R_1}$ is the $\alpha = 1$ case of $\mathcal{R_\alpha}$.

LAMPORT, P. 3 §2.3- Reconfiguration Made Easy

The parameter $\alpha$ introduces a delay before a configuration change takes effect. If $rcfg(C)$ is placed in slot $i$, the new configuration does not become active until slot $i + \alpha$. This allows the system to continue processing additional slots while the reconfiguration moves through the log.

In other words, $\alpha$ defines how many commands can safely be in flight before the new configuration must be used. The case $\mathcal{R}_1$ is simply the smallest delay where $\alpha = 1$.

Noops

To make the reconfiguration happen right away, a client that proposes a reconfiguration command can propose noops as the next α−1 commands. A sequence of successive commands, with successive command numbers, can be batched so that they are proposed, chosen, and executed as efficiently as (using no more messages than) a single command. Thus, α can be made arbitrarily large, permitting the concurrent processing of any desired number of commands.

LAMPORT, $. 3 §2.3- Reconfiguration Made Easy

$\alpha$ can be any positive value. A configuration change only takes effect after $\alpha$ commands have been processed.

If a client wants the new configuration to take effect immediately, it can fill the next $\alpha - 1$ slots with no-op commands. Once those commands are chosen, the new configuration becomes active.

Security

With method Rα, reconfiguration is performed using the ordinary state-machine interface for proposing commands. Only a subset of the clients might be authorized to propose reconfiguration commands, effectively separating the reconfiguration interface from that used to propose other commands

LAMPORT, P. 4 §2.3- Reconfiguration Made Easy

Because reconfiguration commands temporarily restrict concurrency while the change moves through the log, it makes sense to limit who can issue them. Systems often restrict $rcfg(C)$ to a subset of clients so that membership changes cannot be abused or triggered accidentally.
