The Interface

Definition

In the reconfiguration methods based on a sequence of state machines, a state machine is stopped by proposing either a stop command or an infinite sequence of noop commands. If the new configuration is specified by a state-machine command (option R1), then the entire reconfiguration is performed using the ordinary state machine interface. If the new configuration is determined by a special consensus instance that is not part of a state-machine execution (option R2), then a separate interface is required to specify the configuration.

In practice, any of these methods would use a separate interface for issuing reconfiguration requests. The state-machine commands needed to perform the reconfiguration would be proposed by a leader, which would also initiate the special consensus instance in option R2.

LAMPORT, P8 $ §3.4

Reconfiguration can be decided in two places: inside the current state machine or outside it.

R2 runs a separate consensus instance to decide the next configuration. This means the system could determine configuration $v + 1$ before state machine $v$ fully stops.

In theory this allows overlap between the two machines. In practice it adds a second coordination problem and Lamport notes it is unclear whether this is ever worth the complexity.

This leads to R1 being the simpler option.

Which can lead to two problems.

  1. A reconfiguration must be chosen before the machine stops.
  2. Multiple reconfiguration commands might appear in the log.

Stop Sign includes the configuration directly in the stop command. If several are proposed, Paxos simply chooses one like any other command.

Padding works differently. The reconfiguration command is a normal log entry, and padding (a sequence of no-op commands) is used to drive the log forward until the machine stops.

Brick Wall avoids the second issue entirely. Once a stop is chosen at slot i, nothing after i can be chosen. That means the reconfiguration that appears before the wall is automatically the one the system uses.

Lamport’s presentation makes Brick Wall stand out as the cleanest option. The second problem disappears, and the first is handled naturally by Paxos: the log itself determines the configuration once the stop entry is chosen.
