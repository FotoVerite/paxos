Proof

Stopping Paxos prevents a leader from proposing a command if a stop could be chosen for a lower-numbered instance. To describe how this is done, we define $\xi(b,i)$ for ballot $b$ of consensus instance $i$. The value $\xi(b,i)$ equals the command $c$ of case P1 above, and equals $\bot$ in case P2. Stopping Paxos places the following additional constraints on what command a leader may propose in ballot $b$ of instance $i$:

S1. The leader cannot propose any command if there exists some $j < i$ such that it proposed a reconfiguration command in ballot $b$ of instance $j$ or $\xi(b,j)$ is a reconfiguration command.

S2. The leader cannot propose a reconfiguration command if there exists some $k > i$ such that it has proposed a command in ballot $b$ of instance $k$ or $\xi(b,k) \ne \bot$.

It is not hard to show that S1 and S2 prevent instance $i$ from choosing any command if a lower-numbered instance chooses stop. However, S1 can prevent progress if a reconfiguration command is proposed but not chosen by a ballot numbered less than $b$ in instance $j < i$. To eliminate this problem we modify the definition of $\xi$ approximately as follows.

In case P1, $\xi(b,i)$ equals $\bot$ if $c$ is a reconfiguration command proposed in ballot $b' < b$ and some command was proposed in ballot $b''$ of instance $k$ with $b'' > b'$ and $k > i$.

The precise definition and the proof that this works are not trivial.

LAMPORT, P6 $ §3.1.3 - The Brick Wall

For stoppable paxos to work it must prevent leaders from proposing a command if a reconfiguration could have been chosen in a previous slot. This is the same issue that we saw in the joint consensus. To get around this issue he take $pmax$ and reworks it to $\xi(b,i)$. that includes additional logic.

The function $\xi(b, i) has two invariants.

S1: A leader cannot propose a command if there might have been a reconfiguration command decided that is less then the or equal to the current command. This fundamentally leads to S2.

S2: A leader cannot propose a reconfiguration command if there are any inflight proposals greater then the potential $k$ slot for said command.

Once the reconfiguration command is decided on it is easy enough to prove by proof that there will be no more commands. $\xi$ would always emit $\bot$ but what if a reconfiguration command loses the race.

Lamport resolves this by refining the definition of $\xi$ so that stale reconfiguration proposals can be ignored once the system has clearly moved past them.
