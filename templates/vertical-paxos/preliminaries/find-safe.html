Preliminaries - FindSafe

This loop runs while safeVal is still the default safe value and the current ballot has not hit the sentinel. It walks backward through earlier ballots until it either finds a value that still matters or proves a ballot can be skipped.

First it checks whether ballot c already contains a vote:

$ acc \in \{ a \in \mathrm{Acceptors} : \mathit{vote}[a][c] \ne \mathrm{None} \} $

If some acceptor already has a non-None vote in ballot c, the search is over. Set safeVal to that value and return.

Otherwise it waits for enough evidence that ballot c is dead:

$ \exists Q \in \mathit{RQuorums}(c) : \forall a \in Q : $
$ (\mathit{maxBallot}[a] > c) \land (\mathit{vote}[a][c] = \mathrm{None}) $

Wait until there exists some read quorum Q for ballot c where every acceptor in Q has already moved past c and none of them voted in c. Once you have that, ballot c can be treated as empty for this slot, so the search moves on to the previous ballot.

The entire point of FindSafe is to find the most recent earlier ballot whose value still matters for this slot. Either it finds a real vote and returns it, or it proves a ballot is empty and keeps backtracking until a value is found or the sentinel is reached.

For Vertical Paxos, FindSafe has to be patched so it only worries about ballots the system can still actually verify. Once a ballot is complete, there is nothing left there that can surprise the new leader, so the search can stop instead of digging forever through acceptors that may not even be in the system anymore

This is the main trick of the paper. Vertical Paxos needs a place where the search is allowed to stop. That is what a complete ballot is: the point where older history can no longer change what value is safe. VP I introduces that idea. VP II mostly cleans it up and reduces the search to one previous activated ballot.
