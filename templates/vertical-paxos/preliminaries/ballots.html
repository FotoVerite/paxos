Preliminaries - Ballots

In practice, Prev is a function tracking the last active configuration rather than computing a predecessor over an abstract set, with Prev(0) acting as a simple sentinel.

This is a case where the paper leans heavily into formalism without improving the reader’s understanding of how the system would actually be built. The definition of ballots as a subset of natural numbers with an explicit predecessor function is mathematically clean, but it obscures what is operationally happening.

Calling ballots a subset of natural numbers is proof language, not system language. In a real implementation, a ballot is whatever ordered identifier the system can compare and reason about cleanly. In modern systems this is some variant of snowflake id or composite of configuration epoch, ballot-id, and node-id.

The real issue is not mysterious. Some ballots get started and go nowhere. The system still needs to know which earlier ballot actually matters. That is a fair thing to model. The annoying part is how much machinery the paper spends dressing up what is basically predecessor bookkeeping.

Because each ballot is tied to a single leader that determines the value acceptors may vote for, we don’t need to worry about divergent values within that ballot.
